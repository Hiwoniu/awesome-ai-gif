# 微信表情包

把一个原创角色做成一套能提交微信表情开放平台的动态表情。本 Skill 不自带出图模型，出图按这个顺序选：

1. 本机装了 Codex CLI（`codex --version` 能跑）并且已登录：用 `scripts/codex_gen.py` 调 Codex 内置的 image_gen 出图，不需要 API key。见下面“用 Codex 出图”。
2. 当前环境自带图像生成工具：直接用。
3. 都没有：把提示词交给用户，让用户在 ChatGPT 里出图后把图片交回来，再继续后面的步骤。

不管哪种，出图后都要打开图验货（第 3 步），不能只看命令成功。

依赖只有 Python 3 和 Pillow（`pip install pillow`）。脚本都在本目录的 `scripts/` 下，都支持 `--help`。

## 开始前先确认

- 角色是**原创**的。现有 IP、明星脸、真人肖像、影视截图一律不做，直接告诉用户会被拒。用户自家宠物的照片可以做：一般先按照片定稿成卡通角色（见第 1 步）；要复刻的原套本身是真实照片梗图时，不做卡通，直接用宠物照片出真实照片风格（见“复刻：一套静态照片梗图换主角”）。
- 用户要几张。微信一套是 8–24 张，同一套要么全是动态要么全是静态。建议做 10–12 张，挑 8 张以上提交。
- 沿用用户已经定下的角色图、画风和台词，只补缺的部分。

## 流程

### 1. 角色定稿

没有角色图时，按 [角色定稿公式](references/prompts.md#角色定稿) 出一张；用户给的是宠物照片，按 [从宠物照片定稿](references/prompts.md#从宠物照片定稿)，带上照片作参考图。先定画风再定背景：3D、毛绒这类没有描边的画风要出**透明底**，见 [白底还是透明底](references/prompts.md#白底还是透明底)。想要像素风、黏土等其他画风，见 [换画风](references/prompts.md#换画风)。定稿后把“角色”和“风格”两段描述原样记下来，整套出图都复制这两段，中途不改。记下 2–3 个特征件（耳朵形状、尾巴、花纹），后面验货就查它们。

### 2. 选路线

| 路线 | 一次出图得到 | 什么时候用 |
|---|---|---|
| `atlas` 图集轻动效 | 16 张 | 默认先走这条：一张 4×4 图集定下整套姿势，跨张一致性最好 |
| `frames` 六帧序列图 | 1 张 | 需要真实动作（挥手、转身、吃东西）时 |

默认混合：先用 `atlas` 出整套，再挑几张用图集里对应那一格当参考图，走 `frames` 升级成真动作。提示词见 [references/prompts.md](references/prompts.md)。

### 3. 验货（每张出图都要做，实际打开图看）

- 格数和顺序对不对，有没有缺格、错格。
- 每格等大，角色没有越格、没有被裁断。
- 特征件每格都在。
- 没有文字、字母、拟声字（Zz、！、…）。有的格子不用，或局部重绘去掉。
- 白色道具（气团、云朵）轮廓是闭合的。有缺口的去白底时会被整个抠空。
- `frames` 路线：第 6 帧能接回第 1 帧。
- `atlas` 路线：16 个姿势真的不同，不是同一个站姿换表情。

坏格只局部重绘那一格。数量按合格的格数算，不按生成次数算。

### 4. 切图

```bash
python3 scripts/slice_sheet.py atlas.png --cols 4 --rows 4 --out cells/
```

```bash
python3 scripts/slice_sheet.py sheet.png --cols 3 --rows 2 --out frames/
```

有格线时加 `--inset 4` 向内收几像素。

### 5. 合成 GIF

`atlas` 路线，给一格加轻动效（`nod` 点头、`bounce` 弹跳、`sway` 摇摆）：

```bash
python3 scripts/light_motion.py cells/cell_02.png --motion nod --key-white --out result.gif
```

`frames` 路线，把六帧合成：

```bash
python3 scripts/make_gif.py frames/ --key-white --out result.gif
```

两个脚本都会自动缩到 240×240、做 1-bit 透明（阈值 128，主体向内收 1 像素）、超过 500KB 时先减色再减帧。`--key-white` 只去掉和画面边缘连通的白色，角色内部被深色描边围住的白色会保留；描边有缺口的白色部位会和背景一起被抠掉，合成后放到黑底上确认。画面复杂、去底不干净时，先用 rembg 抠图（`rembg i -m birefnet-general in.png out.png`，不要用默认模型，默认模型商用需付费协议），再不带 `--key-white` 合成。

轻动效按姿势选：打招呼、同意用 `nod`，开心、兴奋用 `bounce`，无奈、卖萌用 `sway`。同一套里三种混着用。

### 5½. 加字（可选）

要做“开饭了”“谢谢！”这类带字的表情时，**模型出图仍然不画字**（模型写中文常错字、每帧字形不一样，连播会抖）；字在合成后用脚本加，字迹清楚、每帧一致：

```bash
python3 scripts/caption.py <套目录>/wx-008-吃饭 --text "开饭了" --reveal char --shrink 0.8
```

- `--position top|bottom|left|right` 字放哪边，left/right 默认竖排；`|` 换行（竖排时换列，从右往左）。
- `--shrink 0.8` 把角色缩小并贴到对边，给字让位置。脚本报“字压在角色身上”时就加它或换位置。竖排两列字要缩到 0.7 左右才不会太小。
- `--reveal char` 逐字出现（像打字），在整段循环的前一半出完，字出现的时刻会切开原帧，不受原 GIF 帧数限制。
- 默认蓝字、白描边、外圈一道细蓝边，白底和黑底聊天背景上都看得清；`--color`、`--stroke-color`、`--edge-color` 可改，如生气用红字 `--color "#E8322E"`。
- 整套加字：在各张 `case.json` 写 `"caption": "谢谢！"` 或 `"caption": {"text": "我要|减肥", "position": "right", "shrink": 0.7}`（键名同命令行参数），然后 `python3 scripts/caption.py <套目录>`。
- 第一次加字会把无字原图存成同目录的 `base.gif`，之后改文案重跑都从它开始，不会叠字。

**字体**：脚本先找可免费商用的中文字体（得意黑 SmileySans、站酷快乐体、思源黑体等，放进本 Skill 的 `fonts/` 目录或系统字体目录，或用 `--font` / 环境变量 `STICKER_FONT` 指定）；找不到才退回系统字体并报 WARN。系统字体只能练手，要上架必须换成可商用字体。

文案每张 2–6 个字最好认，和含义词可以不同。不写别人已上架表情里的原句。加完逐张播放，看字有没有挡脸、逐字出现的节奏对不对。

### 6. 配套素材和文案

见 [references/wechat-specs.md](references/wechat-specs.md)。封面 240×240 透明 PNG、图标 50×50 透明 PNG、横幅 750×400 不透明且非纯白且无文字，放进套目录的 `assets/`：

```bash
python3 scripts/make_assets.py cover character.png --key-white --out assets/cover.png
python3 scripts/make_assets.py icon character.png --key-white --out assets/icon.png
python3 scripts/make_assets.py banner banner-raw.png --out assets/banner.png
```

图标默认取主体上半部当头部，做完打开看一眼；没裁对就用 `--head-ratio` 调比例，或用 `--crop x0,y0,x1,y1` 指定源图上的框。横幅要单独出一张有底色、无文字的横图（比例接近 750∶400），脚本只负责居中裁切和缩放。

每张表情配一个含义词（≤4 个字、同套不重复），写进各自的 `case.json`；专辑名称、介绍写进 `pack.json`。

### 7. 机检

```bash
python3 scripts/check_assets.py <套目录>
```

提交前加 `--final`，数量不足、缺 GIF、缺含义词、缺专辑文案、缺配套素材都会算 FAIL。有 FAIL 必须修完；WARN 要逐条实际看图判断。

机检**会查**：GIF 尺寸、体积、帧数、循环；动作是否太小；`frames` 路线首尾是否接得上；所有帧的整圈白边；整套张数和首帧相似度；含义词和专辑文案的字数、重复、“微信”二字；封面、图标、横幅的尺寸、体积、透明与纯白底（看四角）。

机检**不会查**，必须人工看：画面里有没有文字和符号、特征件在不在、局部白边和锯齿、动作是否自然、是否撞 IP、版权主体是否属实。所以退出码 0 只代表规格合格，不代表可以直接提交。把每张表情放到纯黑底上看一遍白边，GIF 实际播放看一遍循环。

“首帧轮廓相近”这条 WARN 是用首帧的差分哈希比的，只看大轮廓，分不出表情：两张都是直立站姿时，哪怕一张笑一张哭也会报。并排看两张，只是表情不同、动作明显不一样可以保留；姿势和动作也一样就换掉一张。

### 8. 交付

告诉用户：做了几张合格成品、机检结果、还有哪些 WARN 没处理、哪些需要用户自己判断。技术通过（机检）、视觉自查、用户认可三件事分开说。不要承诺审核能通过。提交入口是 sticker.weixin.qq.com（电脑端），注册需要大陆居民身份证和已绑银行卡的微信；被拒后在原专辑上修改重提，不要新建一套。

## 用 Codex 出图

`scripts/codex_gen.py` 把提示词文件交给 `codex exec`，让 Codex 用内置 image_gen 按原文出一张图，再把原图从 `~/.codex/generated_images/` 复制到指定位置。每次调用的日志写在输出图旁边的 `codex-<名字>.log`，调用记录（提示词、参考图、原始输出路径、耗时）追加到同目录的 `codex.json`，填 case.json 的出图次数时照着它数。

单张（角色定稿、图集、六帧、横幅都用这个）：

```bash
python3 scripts/codex_gen.py one --prompt character-prompt.md --image photo.jpg --out character.png --transparent
```

`--image` 可以给多次，顺序就是提示词里的参考图 1、2…。`--transparent` 要求透明底。已有同名输出时，旧图改名成 `-v1`、`-v2` 保留，不会覆盖。

复刻整套：见下面复刻第 3 步的 `codex_gen.py remix`，默认同时跑 3 个，一张一两分钟。逐张复刻（每个子目录一份 `prompt.md` + `ref.png`）用 `codex_gen.py each <工作目录> --image photo.jpg`，`--image` 给的图排在前面，子目录里的 `ref.png` 排最后。

- 提示词要先写进文件再交给脚本，不要直接拼在命令行里。脚本自己用 stdin 传指令：`codex exec -i` 能带多个文件，会把后面的位置参数也当成图片。
- Codex 偶尔不照提示词画，比如“捂眼睛”画成了捂嘴。改法：在提示词末尾加一句“重点：……”把关键动作说具体，用 `--only <名字> --force` 重画那一张，旧图会留着方便对比。
- 用户自己没有 Codex 时，脚本会报找不到 codex。这时回到“把提示词交给用户”的做法。

## 从多张宠物照片做一套：先认识它，再定方向

用户给了自家宠物的**多张照片**（不同动作、表情），想“按它的性格出一套”时走这条。比单张照片定稿多两步：先建档、再选方向。

1. **收图、验图**：建议 6–12 张，最少 3 张，至少 1 张正脸清楚。HEIC 先转 JPG，**按 EXIF 转正方向并去掉 EXIF**（手机照片带 GPS 定位）。照片只留本地，`.gitignore` 排除。拼一张照片总览图逐张看：是不是同一只、有没有糊图、动作是否都一样。

   ```bash
   sips -s format jpeg -Z 1600 IMG_0001.HEIC --out photos/p01.jpg    # macOS；再用 Pillow 的 ImageOps.exif_transpose 转正、不带 EXIF 另存
   ```

2. **建档** `profile.json`（模板见 [references/pet-profile.md](references/pet-profile.md)）：
   - **长相**：对着多张照片写毛色分布、眼睛、鼻子、耳朵，定 2–3 个特征件。多角度比单张准，后面每张都按特征件验货。
   - **习惯动作**：每张照片是什么动作、能对应什么表情含义。这是这条流程最值钱的部分：表情来自它真做过的动作。
   - **性格**：照片只能看出表情和姿态，看不出性格。照片上的倾向写上依据（哪几张），再**问主人三个问题**：叫什么、最典型的一件事、像哪种人。两边合起来定 4–6 个性格标签，每个写清“画面上怎么表现”。
3. **给 3 个方向让主人选**：每个方向 = 一句话人设 + 推荐画风 + 12 张表情清单（动作 + 字）+ 主线故事。标出哪几张照着它的真实照片做（📷）。画风跟人设走：偷感、大眼戏、贱萌这类靠神态的，真实照片风格最传神；动作夸张、需要拟人的，用卡通（3D 毛绒、简笔、像素、黏土）。主人也可以混搭。
4. **出图**：
   - **真实照片风格**：不做卡通定稿。挑一张脸部特写、一张全身当身份参考（`--image` 每张给一次），📷 的那张把对应照片放成子目录里的 `ref.png` 当姿势参考。提示词见 [多张照片做一套](references/prompts.md#多张照片做一套真实照片风格)，下方留出加字空间。之后同“照片梗图换主角”的第 3–7 步：先出一张试画风、对照验货、`photo_motion.py` 做镜头动效、`caption.py` 加字。
   - **卡通**：挑 2–3 张最清楚的照片一起带上做[从宠物照片定稿](references/prompts.md#从宠物照片定稿)，再按清单出 4×4 图集，📷 的那几格把对应照片当参考图走 `frames`。之后同主流程。

   ```bash
   python3 scripts/codex_gen.py each <工作目录>/gen --image ref-face.jpg --image ref-body.jpg --jobs 4
   ```

5. 档案留着：同一只宠物以后做变画卡、动态海报，直接用档案里的长相和人设。

## 复刻：一套 GIF 换个角色

输入一套已有的 GIF 表情和一张新角色定稿图，输出新角色的同一套 GIF：每张的动作、帧序和节奏沿用原套，角色外形、配色和画风全部换成新角色。

**先确认来源。** 原套是用户自己做的、或者用户有授权的，才往下做。如果是别人已上架的表情，告诉用户：动作照抄、只换角色属于高度近似的二创，微信审核会按“未授权二创/抄袭”拒，也有侵权风险；建议只拿来练手，不提交。原套里的 logo 一律不复刻；出图时也不画原套的字幕。想要同类“带字”效果，合成后用 `caption.py` 加字（见第 5½ 步），文案自己写，不照抄原句。

1. **新角色定稿**：用户没有就按第 1 步出一张，记下“角色”“风格”两段描述。
2. **拆原套**：

   ```bash
   python3 scripts/remix_extract.py <原套目录或 GIF 文件> --out <工作目录> --character "<角色描述>" --style "<风格描述>" --character-image character.png
   ```

   脚本逐张判断类型并打印出来：
   - `still`：姿势不变、只是整体在点头、弹跳或摇摆。所有 still 的姿势拼成一张 `poses/ref.png`，一次出图画完，合成时自动套回最接近的轻动效（吻合度一般在 0.95 以上）。
   - `frames`：姿势本身在变（挥手、转身）。抽最多 6 个关键帧拼成 `<名字>/ref.png`，每张单独出图。

   打印结果里最后一行是需要的出图次数。判错了可以用 `--force still` 或 `--force frames` 强制。新角色是 3D、毛绒等没有描边的画风时加 `--transparent`，提示词会改成透明底。原套是一次性动画（播完跳回开头）的，机检会报首尾接不上，先用同一条检查量一下原 GIF，原图也报就沿用。
3. **出图**：每个参考图目录里有 `prompt.md`。参考图 1 传新角色定稿图，参考图 2 传同目录的 `ref.png`，提示词用 `prompt.md` 原文。新图存为同目录的 `new.png`。有 Codex 时一条命令画完：

   ```bash
   python3 scripts/codex_gen.py remix <工作目录>
   ```

   已有 `new.png` 的跳过；某张要重画就 `--only <名字> --force`，提示词改过的放在同目录另一个文件里，用 `--prompt-name` 指定。
4. **验货**：新图的网格、格数、顺序要和 `ref.png` 一一对应，每格姿势对得上；角色是新角色，没有残留原角色的花纹、配色；没有文字。坏格局部重绘。
5. **合成**：

   ```bash
   python3 scripts/remix_build.py <工作目录> --out <新套目录> --key-white
   ```

   透明底出的图（`--transparent`）去掉 `--key-white`。

   每张写进 `<新套目录>/<名字>/result.gif`，并生成 `case.json`（route、来源和原 GIF 的逐帧时长已沿用；id、标题、含义词、出图次数留空，要自己补）。打印的出图次数只算换角素材，角色定稿和重画另算。
6. 原套带字的，按第 5½ 步给新套加字（文案自己写）。
7. 之后同第 6–8 步：做配套素材、填含义词和专辑文案、机检、交付。逐张实际播放，对照原 GIF 看动作是否对得上。

## 复刻：一套静态照片梗图换主角

原套是一张张静态的真实照片梗图（比如橘猫照片 P 上人眼人嘴），用户想换成自家宠物。`remix_extract.py` 只吃 GIF，这类走下面的逐张流程。来源确认同上一节：别人的梗图只练手、不提交，原句不照抄。

1. **画风用真实照片，不做卡通定稿。** 这类表情的笑点就是照片感，换成卡通味道就没了。主角参考直接用用户的宠物照片（只做动物，真人照片不做）。
2. **准备工作目录**：每张原图一个子目录，原图存成 `ref.png`，再写一份 `prompt.md`。提示词按 [照片梗图换主角](references/prompts.md#照片梗图换主角)，每张只改“动作和表情”“背景”两行。背景照原图来：抠图白底的出白底，室内照出虚化室内。成品不透明，不需要透明底。

   ```bash
   mkdir -p <工作目录>/01 && cp <原图1> <工作目录>/01/ref.png    # 每张一个目录，依次 01、02…
   ```

3. **先出一张试画风**，看对了再跑其余的：

   ```bash
   python3 scripts/codex_gen.py each <工作目录> --image photo.jpg --only 01
   python3 scripts/codex_gen.py each <工作目录> --image photo.jpg
   ```

4. **验货**：拼一张 ref / new 并排的对照图逐张看，查姿势、取景、道具对得上，主角毛色分布和照片一致，没有画出原图字幕。坏的改那张的 `prompt.md`，`--only <编号> --force` 重画。
5. **做成动图**：原图是静态的，微信一套要么全动要么全静，机检按动图查。照片铺满画面，不能用 `light_motion.py`（会露边），用 `photo_motion.py` 在照片里移动取景框：

   ```bash
   python3 scripts/photo_motion.py <工作目录> --out <新套目录> --motion bounce --set 03=zoom --set 08=shake --set 04=breathe
   ```

   按情绪选：`zoom` 冲镜头（震惊、吼）、`shake` 左右抖（尴尬、生气）、`bounce` 上下颠（笑、得意、比耶）、`breathe` 慢推（委屈、无语、发呆）。每张写成 `<新套目录>/<编号>/result.gif`，动效记在 `case.json` 的 `motion`。
6. **加字**：原图有字的那几张，在 `case.json` 写自己的文案，再跑 `caption.py <新套目录>`。照片梗图常用白字黑描边，字压在照片上、不缩角色：`"caption": {"text": "哈？", "position": "bottom", "reveal": "char", "size": 40, "color": "#FFFFFF", "stroke-color": "#000000", "edge-color": "#000000"}`。这时报“字压在角色身上”是预期的，逐张看字有没有挡住眼睛和嘴。
7. 之后同第 6–8 步：补 id、标题、含义词，做配套素材、机检、交付。

## 套目录结构

```
<套目录>/
├── pack.json          # title、intro、copyright、审核状态
├── character.png      # 角色定稿图
├── assets/            # cover.png、icon.png、banner.png
└── wx-001-<动作>/
    ├── case.json      # meaning（含义词）、路线、引擎、成本、验收
    ├── prompt.md      # 提示词原文
    ├── sheet.png      # 出图原图（图集或六帧图）
    ├── base.gif       # 加字前的原图（加过字才有）
    └── result.gif     # 成品
```
