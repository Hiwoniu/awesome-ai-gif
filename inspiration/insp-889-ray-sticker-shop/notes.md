# 笔记

## 它是怎么做的

一张角色图定整套的形象，先在 pack.json 里把每张表情的配字和动作都规划好，再用 dry-run 看要生成多少张、大概要花多少钱，确认没问题才真正生成。生成走 4×4 精灵图：同一张表里出连续动作帧，再切帧、用 Pillow 合成 GIF，自动压到微信要的 240×240、500KB 以内。最后按微信规范逐项检查，不合格的列出来，同时把封面、图标、横幅、赞赏图、上架文案和交付压缩包一起整理好。没有 API key 也能用：先导出提示词去外部出图，再把图放回来合成。花费记在 costs.jsonl 里。

## 我们怎么用

借它“先规划整套、再批量生成、最后按平台规范检查”的流水线：我们自己的原创角色也可以先写一份 pack.json，把表情配字和动作一次定好；dry-run 预估费用这一步值得学，避免生成到一半才发现超预算。240×240 压 500KB 内的检查逻辑可以直接当作微信投稿前的自检清单。不用它的示例角色和文案，只借流程。
