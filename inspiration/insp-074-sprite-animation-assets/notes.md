# 笔记

## 它是怎么做的

- 核心判断写在最前面：动画素材的关键不是单张图好看，而是同一个角色在每一帧里身份一致、尺寸一致、背景透明、动作能循环。
- 工作流分七步：先定义规格（状态名、每状态帧数、画布尺寸、输出格式）；再生成或确认一张 canonical base image，作为所有帧的身份锚点；然后分状态生成连续帧，每组帧用同一角色参考和同一纯色背景或透明背景策略；接着目视 QA（身份一致、动作连贯、无漂浮杂点、无文字、无阴影地面、无裁切）；需要时先把每帧处理成透明 PNG；再用 compose_sprite_set.py 组 atlas，并可导出每个状态的 GIF 预览；最后检查 sprite-set-report.json，再打开 atlas 或 GIF 做最终验收。
- 组装靠 manifest 描述：cell 宽高、列数、每个状态的名字、行号、帧文件列表与每帧时长；脚本把每帧居中放进固定 cell，未使用的 cell 保持全透明。
- 提示词要点是锁身份：每组动画都要锁定轮廓、比例、脸、配色、描边风格与配饰，背景用可抠除的纯色，不要阴影、文字、场景、运动拖影、帧编号或网格线。
- 验收标准明确：每状态帧数符合 manifest、所有帧透明背景或可干净抠透明、动作能循环且首尾不明显跳变、未使用格子必须全透明；GIF 只是预览，最终交付优先给 PNG 帧或透明 atlas。

## 我们怎么用

- 借先定身份锚点的流程：我们的多状态精灵表也可以先定一张 base image，再分状态出帧，而不是每组各画各的。
- 借 manifest 的组织方式：状态名、行号、帧文件、帧时长写进一个 JSON，组装与验收都以它为准。
- 借每状态导出 GIF 预览的做法：atlas 是交付物，GIF 是给人看的预览，两者分开。
- 借目视 QA 清单：身份一致、动作连贯、无漂浮杂点、无文字、无阴影地面、无裁切，可以直接放进我们的验收流程。
