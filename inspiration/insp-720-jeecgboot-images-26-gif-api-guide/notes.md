# 笔记

## 它是怎么做的

这篇是 JeecgBoot 团队对 ChatGPT Images 2.6 的实测解读，按“能做什么 → 两个模型怎么选 → API 怎么用 → 适合哪些场景 → 注意什么”拆开讲。核心是 API 侧把 GIF 变成了原生输出格式：请求里指定输出格式为 gif，再给帧数（2～64 帧）和单帧时长（毫秒），不用在服务端自己拼帧。

帧数与帧时长的配比按场景给了经验表：表情包、按钮动效用 8–16 帧、每帧 80–120 毫秒，一圈 1–2 秒；产品旋转用 24–32 帧、每帧 60–80 毫秒；叙事型小动画接近 64 帧上限，但文件体积会明显上涨。先少帧验证，再逐步加帧。

两个模型分工明确：Flare 速度优先（最快约 6 秒出图，适合批量出图、要动图、对时延敏感的场景），Sunburst 质量与多轮编辑一致性优先（支持 SVG 导出与局部精修）；也可以 Flare 出草稿筛方向、Sunburst 定稿精修。

另一个玩法是精灵图转动画：先让模型生成一张含多个姿态的精灵图，再转成连贯动画，官方演示里一条锦鲤就是这样从几个分解动作拼成流畅游动。

限制也写得很实在：GIF 最多 256 色、没有半透明通道，渐变和照片级画面会出现色带；帧间一致性要逐帧验收，角色中间几帧容易“变脸”；64 帧大尺寸 GIF 体积几 MB，上网页或邮件前要先压缩。

## 我们怎么用

借它的参数表来定我们自己的出图规格：微信表情包先按 8–16 帧、每帧 80–120 毫秒起测，产品类循环再试 24–32 帧、每帧 60–80 毫秒。借 Flare 草稿加 Sunburst 定稿的两段式分工，定稿前先少帧验证效果。精灵图转动画的路线可以和我们已收的精灵表做法对照着用。只借参数与流程，不照搬文中的小猫、锦鲤等示例形象。
