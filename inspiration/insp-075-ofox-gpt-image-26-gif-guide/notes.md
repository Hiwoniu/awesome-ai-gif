# 笔记

## 它是怎么做的

- 把 2.6 做 GIF 的三条路线摆在一起比：直接在 ChatGPT 里要 GIF、走原生 Images API 调参数、以及先要一张精灵表再本地拼装；每条路线写清适合谁、代价是什么。
- API 路线给了实测参数：一次 Flare API 实测出 9 帧，帧数与帧时长都有可调范围，适合要精确控制的场景。
- 提示词按六段组织：输出格式、主体、动作、不变量、风格、验收；不变量一段专门写死机位、背景、角色外观，验收一段要求末帧接回首帧。
- 验收标准是看满一个完整循环、再查帧时序：动作是否按顺序出现、首尾是否跳帧、文字有没有逐帧错乱。
- 注意：这篇与已收的 insp-032（同一作者的 Seedream 出帧导出流程）是不同文章、不同主题，不重复。

## 我们怎么用

- 借三路线选择表：做 GIF 先判断走 ChatGPT 直出、API 调参还是精灵表拼装，而不是默认只用一种。
- 借六段式提示词结构：输出、主体、动作、不变量、风格、验收六段分开写，重点是把不变量与验收单独成段。
- 借 API 参数的写法：帧数与帧时长按场景给范围，而不是固定一个值。
- 借验收标准：看满循环、查帧时序，可以直接放进我们的验收清单。
