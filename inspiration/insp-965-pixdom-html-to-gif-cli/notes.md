# 笔记

## 它是怎么做的

Pixdom 不走图片模型路线，而是把动效写成 HTML/CSS，再用 Playwright 把浏览器里的动画逐帧截下来，经 Sharp 与 FFmpeg 合成 GIF/MP4。作者的痛点是录屏加剪辑软件来回调尺寸太慢，于是做成命令行工具，一条命令出图。

三个值得注意的设计：

- `--auto` 自动模式：先给 DOM 元素打分找到主内容，再从 CSS 里算出动画周期的最小公倍数当总时长，按缓动类型（ease-in-out 之类）定帧率，渲染前把算出的元素、时长、帧率、总帧数打印出来，可手动覆盖。
- 19 个平台预设：LinkedIn 帖子、X 视频等尺寸直接内置，不用每次查尺寸表。
- MCP 服务器：`convert_html_to_asset` 只做渲染，`generate_and_convert` 先让 Claude 写 HTML 再渲染。也就是说 Agent 一句话就能完成“写动效、渲染、出 GIF”全程。

## 我们怎么用

动态海报可以多一条代码路线：先让模型写一段 HTML/CSS 动效（标题、装饰、循环节奏都在代码里精确控制），再用这类工具渲染成 GIF。特别适合文字排版要求高、图片模型总把字画坏的海报：字在代码里是真文字，不会画错。

换掉的部分：对方的例子是 LinkedIn 推广图，我们换成自己的原创角色海报；平台预设只借思路，按我们实际发布的平台（微信、小红书、X）自己定尺寸。

注意：这是 2026 年 3 月的项目，版本较旧，装之前先看仓库最近的更新情况；渲染的是代码动效，画面丰富度取决于写 HTML 的能力，不适合需要手绘质感的画面。
