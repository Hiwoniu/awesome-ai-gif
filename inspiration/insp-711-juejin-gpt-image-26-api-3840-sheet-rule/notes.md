# 笔记

## 它是怎么做的

作者 11 月 5 日实测了 7 单，核心发现是一条帧图集规则：GPT Image 2.6 把 GIF 所有帧排在同一张图集上一次画出，图集长边不能超过 3840 像素；帧数先向上取 2 的幂再排网格（6 帧按 8 格排 4×2 或 2×4，9 帧按 16 格排 4×4）。所以 6 帧 1024 方图横竖排都要 4096，直接失败且不扣费；改成 832 方图（图集 3328×1664）25 秒成功，六帧挥手机器人、每帧 150ms。由此推出单帧上限：5–8 帧短边≤960、长边≤1920，9–16 帧两边≤960；并给了发请求前先算图集尺寸的校验函数思路。

另一条线是标注图改图：做一张与原图同尺寸、只画红圈箭头批注的透明 PNG，通过 markup 参数发过去，模型只改圈住的部分，标注本身不画进结果；实测把海报上的两只罐子换成了小盆栽，其他元素不动。

## 我们怎么用

走 API 出 GIF 时，先按帧数算好单帧上限再发请求，避免 1024 这类超限尺寸白跑；精确尺寸没必要时直接传比例加档位，让平台自动缩帧。局部改图时借透明标注图的做法：圈出要改的区域、写清只改这一处，其余锁死。示例的机器人与小鸟都是对方实测用的形象，只借规则与做法，不复用画面。
